# 共享记忆改名 `MEMORY.yaml`（破 ADR-0004 的文件名冻结）

工作区根的共享记忆从 `.learning/MEMORY.md` 改名为 **`.learning/MEMORY.yaml`**，内容改成 **YAML 分节**存放；
随包的骨架（`templates/` 下的 `MEMORY.md`）同步改名为 `MEMORY.yaml`。**节一个都没换**，仍是
「我是谁 / 教学偏好 / 学习习惯 / 跨科目观察」，只是节名从 `##` 标题变成了一级键。

为什么非改不可：下一步要把这份记忆拆开用——**画像进上下文、干活笔记不进**。今天的形状
（`##` 标题 + 自由 bullet）没有机器可读的节边界，谁想按节取用都得自己写一个 Markdown 解析器，
而节里写什么全凭行文，取出来的是没法对账的一段散文。键是 YAML 给的：节名、节里的条目标题
（「现有技能」「各领域当前水平」…）都成了结构，取哪几节是查表，不是猜。

这是 [#189](https://github.com/Miaotofu01/Study-Mate/issues/189) 定下的。

## 破 ADR-0004 的边界

[ADR-0004](0004-学习数据格式冻结与例外.md) 的承诺是「学习工作区的布局、文件名与目录结构不动」。
本次破的是那句话里的**文件名**一处，范围写死：

- **动的**：`MEMORY.md` 这个名字（模板名与工作区里的名字一起动），以及这份文件自己的内容形状。
- **不动的**：目录结构（`.learning/`、`.learning/subjects/<slug>/` 与科目里的一切）、五份 schema、
  其它任何文件名。ADR-0004 的冻结除这一处与它自己那条状态词表例外之外**仍然有效**。

## Considered Options

- **兼容旧名一段时间**（读侧先找 `MEMORY.yaml`、没有再退回 `MEMORY.md`）：迁移期零成本，但盘上会有
  两个都叫「共享记忆」的位置，读侧那条兜底分支没有自然的删除时机——它能一直活下去，于是「改名」
  永远只完成一半，第三份夹具、第四处注释会继续照旧名写。要断就断干净：读侧不兜旧名、不留兼容分支，
  旧名从此就是一份普通文件。
- **不破冻**：名字和形状都不动。两条路都不行——把 YAML 塞进 `.md` 是让文件名说谎；继续用 `##` 分节
  就是上面那个「没有机器可读的节边界」的问题原样留着，而这次改名的全部理由就是它。
- **连目录结构一起重划**（顺手把 `.learning/` 改个名、把科目文件也搬一搬）：ADR-0004 要保护的是
  学生真实积累的学习档案；为了省一次改名而动整片目录，代价与收益不相称。

## Consequences

- **旧工作区要自己改个名**：一条 `mv .learning/MEMORY.md .learning/MEMORY.yaml`。不随包提供迁移脚本——
  改的是名字，节一个都没动；而读侧拿这份文件当**文本**读（注入、摘要、载荷都取原文），改完名原样能读。
  真到了按节取用那一步，内容形状才需要跟着模板走。
- **读侧不认旧名**：`.learning/MEMORY.md` 不再被当成记忆——答疑会话不注入它、摘要工具回报 `present: false`、
  图片库载荷里是空串、监听域把它报成普通的 `workspace` 变更。这几条各有断言钉住（其中「全仓一处旧名都不留」
  那条是否定式扫描：`scripts/tests/test_memory_rename.mjs`）。因此 **CHANGELOG 与 ADR 是唯一还能提旧名的地方**
  ——前者由发布流程生成、不许手改，后者是决策记录，必须同时写出旧名与新名才记得下这次改名。
- **模板名要三处一起动**：DSH 侧与两个无头宿主插件（Codex/ChatGPT Work、Antigravity）都按名复制
  `templates/MEMORY.yaml`。漏一处，那边的「首次初始化」就会去找一个不存在的模板。
- **宿主契约不动**：摘要与载荷里的字段名（`markdown`、`memory_md`）保持原样——它们是插件与阅读端之间的
  字段契约，这次改的是盘上的文件名，不是契约。名字里的 `md` 因此暂时与文件后缀不一致，属于已知的措辞债，
  等真去动那份契约时一起收。
