# StudyMate Web Chat 工具面与主动检索设计（RFC 专题）

> 性质：**架构设计与演进调研（RFC）**——针对 Web 独立运行时环境下 Chat 角色工具面边界、与上游插件基准能力的差距，以及「主动检索（Resource Scout）」的实施路径进行系统性评估与规划。
> 关联文档：系统整体架构见 [StudyMate-Web_开发与计划.md](../StudyMate-Web_开发与计划.md)；建课链路见 [StudyMate-Web_项目建课链路.md](StudyMate-Web_项目建课链路.md)。

---

## 1. 背景与定位差异

在上游 DSH 插件体系中，学习总控 Agent（`preset/learning/agent.cordis.yml`）依托宿主环境拥有丰富的本地执行工具（终端、完整文件读写、作业系统、联网检索、多级派工等）。

在 **StudyMate Web 独立运行时**中，系统采用了**“薄前端 + 专用后端业务链”**的工程架构：
- 复杂业务逻辑（如大纲门禁、课件渲染、文件落盘、并发锁）由后端 Python 业务链确定性保证，而非完全交由开放式 Agent 自由发挥；
- 会话内的 Agent 主要承担对话辅导与特定工具调用；
- 这种差异导致了当前 Web Chat 工具面较为收敛，并在从零建课的“资料检索与采图”链路上暴露了结构性空白。

---

## 2. 工具面对比与差距分析

下表对比了插件总控配置与当前 Web Chat 环境的工具能力：

| 能力维度 | 插件预设 (`preset/learning/agent.cordis.yml`) | Web Chat 现状 | 差异与边界考量 |
|---|---|---|---|
| **终端执行** | `bash` / `pwsh` | **无** | Web 环境出于沙箱隔离与安全性考虑，默认不向对话 Agent 开放宿主终端执行权。 |
| **文件与大纲** | 任意 `fs` 读写 | **只读与结构化**：`read_course_file` / `list_workspace` / `get_course_outline` | Web 侧写盘操作严格由后端编排链路（`build.py` / `produce.py`）托管；大纲及掌握度由 `get_course_outline` 结构化提供。 |
| **学习记录检索** | `fs-search` | **结构化查询**：`read_misconceptions` / `list_learning_records` | 提供专用的误解概念筛选与历史评估记录汇总，无需 Agent 盲目扫盘。 |
| **后台作业** | `jobs` | **无** | 异步长任务由后端 Task / Worker 承载。 |
| **技能机制** | skill 目录 + 动态按需加载 | **只读**：`read_skill` | 链路核心技能由后端在提示词组装阶段全文注入。 |
| **规划能力** | `goal`、`plan-mode`、`compaction` | **无** | 会话上下文管理由后端动态组装与截断保障。 |
| **多级派工** | `subagent(spawn, maxDepth=2)` + `workflow-ptc` + `ralph` | **支持（K4）**：`call_subagent` | 实现了 K4 子代理工具，支持分派 `generate`、`produce_content`、`produce_quiz`、`grade` 等专业角色。 |
| **人机交互** | `ask_user`、`todo` | **模式切换**：`start_course_interview` | 支持在对话中自主切入建课与方向盘问模式。 |
| **联网能力** | `web(fetch + search)` | **无** | **核心缺口**：Agent 无法主动联网检索外部教学资料（见下文主动检索方案）。 |
| **产物交付** | `present` | **无** | 产物直接落盘进工作区，前端通过 API 获取展示。 |

> 注：2026-10-10 已实施落地规划项 #16（K4 子代理工具 `call_subagent` 与 `generate.py` 统一门禁）和 #29（Chat 工具面扩容 `get_course_outline`、`read_misconceptions`、`list_learning_records`），学习者在建课后的全周期辅导链路已完整闭环。当前剩余核心能力差距主要集中在主动联网检索（规划项 #9）。

## 3. 主动检索（Resource Scout）问题剖析

### 3.1 现状与痛点
1. **资料清单为空**：在 Web 界面从零发起建课（Interview 盘问收口）时，由于没有前置的互联网检索环节，生成的 `RESOURCES.md` 往往没有可用的外部参考链接。
2. **采图结构性跳过**：后续采图阶段（`image_scout.py`）依赖从 `RESOURCES.md` 解析 URL 进行抓取。在资料清单为空的情况下，采图阶段必定以“0 张图片”瞬间结束（前端标记为「采图 · 跳过（无参考资料）」）。
3. **教学体验受限**：缺乏外部真实文档和图例，导致生成的概念和实操课件以纯模型知识为主，丰富度受限。

---

## 4. 主动检索可选演进路线

针对主动检索的落地，目前梳理出三条可选实施路线：

### 路线一：纯后端最小检索（推荐的轻量路线）
- **设计思路**：对齐现有的 `image_scout` 模式，在后端建课链中引入一个轻量级的 Python 检索服务（如通过特定搜索引擎 API 或离线文档库抓取相关权威链接）。
- **优势**：
  - 不引入复杂的 Agent 自主决策，稳定性高，耗时确定；
  - 检索产物直接标准化写入草稿目录的 `RESOURCES.md`，天然激活后续采图链；
  - 保持 Web 架构现有的“后端可控编排”原则。
- **代价**：需配置稳定的外部搜索提供商或依赖合规的公网检索接口。

### 路线二：架构简化，裁剪采图阶段
- **设计思路**：承认本地独立 Web 运行时以“核心知识传授与实践”为本，在无外部资料输入时彻底移除采图编排阶段，避免给用户造成“采图空转”的困惑。
- **优势**：链路最短，建课流程更快速高效，完全消除外部网络依赖。
- **代价**：生成的课件缺乏自动化配图，视觉丰富度低于插件版。

### 路线三：Agent 联网检索工具化（K4 总控路线）
- **设计思路**：为 Chat Agent 开放标准的 `web_search` 和 `web_fetch` 工具，在盘问阶段或大纲生成阶段，由模型自主判断何时检索并汇总资料。
- **优势**：最大程度对齐插件版灵活性，具备跨领域自适应能力。
- **代价**：
  - 依赖底层模型网关对工具调用及联网的高可用支持；
  - 显著增加建课耗时与 Token 消耗，偶发网络波动易导致门禁打回。

---

## 5. 结论与拍板指引

- **当前状态**：保持现状防御性处理（无资料时明确标记为跳过，不阻塞建课落盘）。
- **决策建议**：若维护者希望补齐课件丰富度，优先建议采用**路线一（纯后端轻量接入）**；若追求轻量与离线自包含，建议评估**路线二**；路线三宜作为远期架构探索（挂规划项 #16）。
