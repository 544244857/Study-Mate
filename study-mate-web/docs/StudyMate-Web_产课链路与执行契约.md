# StudyMate Web 产课链路与执行契约

> 性质：**技术规范与执行契约**——定义 StudyMate Web 运行时单节点课件生产（`produce.py`）的完整流程、角色分工、交付物门禁、复用策略与异常处理。
> 关联文档：整体建课及基准链路详见 [StudyMate-Web_项目建课链路.md](StudyMate-Web_项目建课链路.md)；架构全局约束见 [StudyMate-Web_开发与计划.md](../StudyMate-Web_开发与计划.md)。

---

## 1. 概述与触发入口

### 1.1 触发机制
- **主要入口**：在已关联科目的聊天会话中，由 Agent 调用 `produce_lesson` 工具（或建课完成卡触发同款调用）。
- **工具权限边界**：`produce_lesson` 与 `assess_node` 仅对**已关联科目的会话**开放，未关联科目的会话不得调用。
- **时间预算（Wall-clock Budget）**：工具执行在 Agent 单轮交互的 `asyncio.wait_for` 之外，整轮产课受全局超时限制 `ORCH_MAX_SECONDS`（默认 1800s，可通过环境变量 `STUDYMATE_ORCH_MAX_SECONDS` 覆盖）。

### 1.2 节点选择与顺序门禁
- **默认节点选取**：当调用方未传递 `node_id` 时，系统**严格按大纲顺序选取第一个尚未产出课件的节点**（与 `curriculum.yaml` 节点声明顺序一致，不沿用会话上下文注入的节点聚焦）。
- **顺序门禁（Sequential Gate）**：检查目标节点之前所有节点的课件文件是否已齐备（已有 `.md` 课件数量必须与目标节点位次严格匹配）。禁止跨节点跳跃生产，若位次不符立即报错终止。

## 2. 课型分支与角色派工

系统根据节点课型（`kind ∈ {概念, 实操, 实验}`）决定派工编排流程：

```
                    ┌── 概念课 ──► 讲解派工 ──► 出题派工 ──┐
                    │                                      │
[检查顺序门禁] ─────┼── 实操课 ──► 讲解派工 ──► 出题派工 ──┼──► 渲染与检查 ──► 门禁自检
                    │                     (含完整 Lab 树)  │
                    │                                      │
                    └── 实验课 ───────────────► 出题派工 ──┘
                                          (含说明页 + Lab 树)
```

### 2.1 非实验课（概念课 / 实操课）
1. **阶段一：讲解生成（`stage 讲解`）**：
   - 派工角色：`produce_content`（注入 `lesson-design` 技能）。
   - 产物：`lessons/<NNNN>-<id>.md`（四位编号与 slug 命名）。
2. **阶段二：出题生成（`stage 出题`）**：
   - 派工角色：`produce_quiz`（注入 `layered-practice` 技能）。
   - 产物：`lessons/<NNNN>-<id>.quiz.json`。
   - **实操课 Lab 要求**：若课型为实操课（`kind=实操`），出题角色必须同时交付完整的 Lab 实操任务树（见下文 2.3 节），正文中需包含指向 Lab 的相对跳转入口。

### 2.2 实验课（`kind=实验`）
- **无讲解阶段**：实验课不派工讲解角色，直接由出题角色承担生产。
- **产出交付**：一次性产出「实验说明页 `lessons/<NNNN>-<id>.md` + 完整实操任务树 `lab/`」。说明页路径必须匹配四位连续编号。

### 2.3 实操 / 实验课 Lab 交付契约（Required Artifacts）
实操课与实验课必须同时生成且验证以下三项产物（缺一不可，缺失时拒绝 Promote 并判定失败）：
1. **阶段实操指南**：`lab/<NNNN>-stage/README.md`
2. **参考实现指南**：`lab/solutions/<NNNN>-stage/README.md`
3. **全局 Lab 总索引**：`lab/README.md`（需保留既有历史节点索引，并增补当前节点条目）

## 3. 派工模式与备用回落

后端支持两类派工调用模式：

| 模式 | 标识 (`execution_mode`) | 行为机制 |
|---|---|---|
| **工具循环模式** | `tools` | 优先采用 K3 工具循环（`_role_tool_loop`），提供 `write_deliver_file` 交付文件和 `run_check` 本地渲染检查回喂，模型可自主迭代修正。 |
| **单次回落模式** | `fallback` | 当模型声明不支持工具、或工具循环耗尽无交付文件时回落至单次直接派工。 |
| **单次直连模式** | `single_call` | 针对特定测试模式或纯直接调用的备用路径。 |

### 关键契约与展现规则
- **真实状态呈现**：备用角色在任务卡如实展示 `execution_mode`、`fallback_reason`、`max_seconds`、`elapsed_s` 与 `message`。
- **Envelope 真实语义**：单次派工返回 envelope 仅代表收到回复并成功解析格式，**不等于自检通过**，必须严格通过后续门禁检查。
- **进度通知**：工具循环执行中每隔约 10s 发送一条进度心跳 notice，避免前端界面冻结。

## 4. 产物复用判定与强制重做

为避免重复消耗 token，系统具备既有产物智能复用机制，但设置了极为严格的安全判定门槛。

### 4.1 允许复用的判定条件
仅当以下条件**全部满足**时，才允许复用已有文件并跳过角色派工：
1. **本轮无新生成文件**：该角色在当前轮次没有输出新文件。
2. **非强制重做**：请求参数中 `regenerate == false`。
3. **上下文检查已通过**：本次生产上下文中的 `check_passed` 标志为 true。
4. **必需交付物齐备且有效**：
   - 该角色必需的目标文件（出题对应 `*.quiz.json`，其余对应 `*.md`）在目标目录存在；
   - 目标文件可读且内容非空；
   - 目标文件必须为合法 UTF-8 编码文本。

### 4.2 强制重做规则（禁止复用）
以下场景一律**禁止复用**，必须重新触发全量派工：
- 请求中明确传入 `regenerate=true`（且必须严格为布尔类型，并显式指定 `node_id`）。
- 门禁检查不通过触发的自修打回重派轮次（`retry round`）。
- 质检工单重试（`ticket retry`）。

## 5. 渲染校验、自检打回与工单流转

### 5.1 门禁检查
- **引擎调用**：通过子进程调用自带引擎脚本：
  1. `render_lesson.py`：将 Markdown 课件渲染为 HTML 产物。
  2. `check_lesson.py`：对渲染后的 HTML、结构和资源引用做严苛检查。
- **DOM 解析规范**：`check_lesson.py` 内部使用 `HTMLParser` 仅提取真实的 `href` 与 `src` 属性，不将代码块（`<pre><code>`）中的转义示例代码误判为缺失资源。

### 5.2 打回与自修策略
- **最大打回轮次**：`MAX_RETRIES = 2`。
- **计数隔离原则**：
  - `repair_rounds`：记录模型层面的修复派工轮次。
  - `rechecks`：当问题归属纯粹为总控共享资源缺失时，由系统补充共享资源后触发一次复检，**不占用模型修复轮次**，也不虚报打回次数。
- **责任归属打回**：根据检查器输出的 problems owner 精准重派（讲解问题重派内容角色；出题受锚点和内容影响联动重派）。

### 5.3 质检工单转人工（Handoff）
- 打回轮次耗尽仍未通过门禁时，系统创建 `kind=produce` 质检工单，持久化至 `data/tickets.json`，同时推送 `handoff` 和结构化错误事件。
- **工单处理动作**：
  - `recheck`：仅重新运行本地渲染与门禁检查。
  - `retry`：重新进入 `dispatch()` 工具循环进行完整修复派工。

## 6. 审计与统一错误处理

- **审计追踪**：每次生产绑定编排键 `produce-<slug>-<node_id>`，全量事件追加写入 `data/audit/produce-<slug>-<node_id>.jsonl`（包含派工、工具调用、模式降级记录等）。
- **统一错误契约**：异常与中断统一采用 `ErrorInfo` 结构化对象（包含 `code`、`status`、`summary`、`detail`、`retryable` 等属性）。
- **取消与停止作用域**：停止操作具有 `(session_id, turn_id)` 作用域，用户显式停止或系统超时触发时，任务非 running 状态下自动隐藏当前阶段并停止关联的派工任务。
