```text
lab/
├── README.md                 ← 本文件（lab 说明书）
├── <NNNN>-<主题>/             ← 任务目录：你要动手的地方
│   ├── 任务单.md              ← 留白任务（写在这张单子上）

├── solutions/<NNNN>-<主题>/   ← 参考解（与任务分开放，做完才看）
├── 干净态.sh                  ← 跑一遍「任务还没做」那一态

└── 自检.sh                    ← 出题角色交件前跑：按顺序把上面两个入口各跑一遍
```

之类，就在 `断言.sh` 里 `exec` 那个解释器——「证据」里那条命令仍只是 `sh check.sh`。

## 六、判分入口怎么跑

两个状态各有一个**运行入口**（都只负责摆盘与转述，判分入口仍然只有 `check.sh` 一个）：

```sh
sh 干净态.sh    # 干净态：任务留白、参考解仍在 solutions/ 里
sh 作答态.sh    # 作答态：把 solutions/<NNNN>-<主题>/作答 摆进临时副本再跑
sh 自检.sh      # 两个入口按顺序各跑一遍（出题角色交件前跑这个）
```

`check.sh` 只回事实（参数、断言的输出、退出码），**非零不是判决**：判不判、怎么判，
由跑手记下的事实与总控按 `layered-practice` 第五节的三档做。两个入口都在**临时目录**里跑，
跑完连痕迹一起删——你的 lab 与参考解一个字节都不动；它们的退出码就是那一次 `check.sh` 的退出码，原样转述。
